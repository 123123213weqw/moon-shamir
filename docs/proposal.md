## 一 项目目标与应用场景

Shamir 把一份高熵秘密变成 n 份份额、任意 k 份即可恢复、任意 k−1 份对一切可能秘密不可区分——该保证是有条件的：秘密本身须高熵、系数种子须均匀满宽（本库以 seed_hex 支持全宽 64 位注入，数值字段 53 位为兼容上限而非建议值）。面向私钥、种子、派生密钥材料的分片备份：单点存放的密钥一次事故即永久丢失，一次泄露即彻底失守；分片后丢失部分份额不损失秘密，窃取不足门限的份额学不到任何信息。这不是计算上的困难，是信息论意义上的不可能；但低熵秘密（六位恢复码等）不满足条件——公开完整性标签使单份份额即可枚举还原（仓库内 scripts/lowentropy-demo.py 以 2.6 秒完成 10⁶ 枚举的可执行演示），低熵输入必须先经 KDF 拉伸。这也是与口令管理器方案的本质差别。

选此方向依据可复现查证：2026-11-04 克隆 mooncakes.io 注册表索引（3557 个模块）检索 shamir / secret sharing / threshold scheme / key shard / slip39 / bip39，无一实现；2026-11-11 复检（索引已扩至 23151 个模块条目）结论不变——全部命中为本模块自身，slip39/bip39 仍无，新出现的 GF256 包为网络编码方向而非秘密分享——在压缩、SAT/SMT、TLS、WebAuthn 均有人占位的生态里，密钥分片备份是空位。项目没有把已有存储或加密库改名复用为主体，也没有继承本仓库此前任何提交之外的源码。

## 二 已完成交付能力

| 能力 | 实际机制 | 输出及边界 |
|---|---|---|
| split | 每字节一条 GF(2⁸)（AES 多项式 0x11B）随机 k−1 次多项式，份额 i 为各多项式在 x=i 处取值 | hex 或 UTF-8 文本秘密 ≤16 KiB；2≤k≤n≤255；熵由调用方注入——seed_hex 全宽 64 位（数值 53 位为兼容上限）或口令 PBKDF2 派生 |
| combine | 拉格朗日插值常数项，确定性取最小 x 坐标 | 不足 k 份直接拒绝——不存在"恢复出错值"的输出可误用 |
| diagnose | 穷举全部 k-子集（≤12 份、k≤6，至多 C(12,6)=924 次插值） | 与每个法定人数都不一致的份额被点名——损坏份额是被定位的，不只是被怀疑 |
| verify | 执行 combine 同款插值但不返回秘密；可选 secret_hex 断言 | 持有方可证明份额集属于已知秘密而响应不携带新信息 |
| reshare | g = f + h，新秘密多项式由旧份额插值加零常数项随机多项式合成 | 无秘密过内存铸造全新 (k′,n′) 分片；门限可升不可降；旧代份额失效 |
| HMAC 认证 | 可选 mac_key_hex，份额携带 HMAC-SHA256 标签前 64 位 | 防整个份额集被替换重标——公共标签防不住的攻击；对密钥持有者无效 |
| 份额编码 | hex（默认）、base64、words（一词一字节加两词校验和，256 词表冻结于源码） | 同一集合内自由混用；每份额自报编码；words 可纸笔誊抄 |
| 口令种子 | PBKDF2-HMAC-SHA256（RFC 8018，向量钉死），首 7 字节移入 53 位 | split/reshare 可用 password 代种子；kdf 操作独立钉死派生 |
| 使用入口 | MoonBit 公共库 execute/run、JSON CLI、scripts/shamir.mjs 六动词命令行 | 单 JSON 应答，错误信封与退出状态可被脚本消费 |

## 三 核心工程机制

安全模型以条件式陈述并附可执行反例（docs/security.md）：门限保证依赖两个前提——秘密高熵（公开标签对低熵秘密是穷举验证器，演示脚本三秒内从单份份额还原六位码）与种子均匀满宽（seed_hex 全宽 64 位，全程 UInt64 通道，数值 53 位上限如实标注；该重构同时修复了口令派生路径经 Double 中转的静默精度损失）。正确使用姿势一句话：以密码学随机源生成 64 位 seed_hex，只分片高熵材料，人造口令先经 kdf 拉伸，需要防替换时叠加 mac_key_hex。熵与时间一样是注入的：系数流由调用方传入种子的 SplitMix64 生成，库从不读取环境随机源。同一 (secret, seed) 在 js/wasm/wasm-gc/native 四后端逐位复现同一份额——这正是独立 oracle 能逐份额对拍的前提，也把"随机性不可测"转化为"可复现可审计"。GF(2⁸) 在本项目里被构造了三次：实现的指数/对数表乘法器（生成元 3，乘法即对数相加）、保留作见证的移位归约乘法器、oracle 里第三条路径的 Python 表——三者被穷举等价（65536 对全查）与逐份额对拍同时约束，一个 bug 要活过三套独立构造的会签。

门控层次是分级的，每一级都如实声明自己的强度。阈值以下的 combine 直接拒绝，不存在误用为"部分恢复"的输出；CRC-32 与 SHA-256 标签捕获损坏与混入，但它们是公开可重算的，不能防恶意替换——文档原话如此；HMAC 标签是唯一防替换的一层，语义钉死：有 mac 无 key 拒绝（静默跳过会被读成成功）、有 key 无 mac 拒绝（静默空转会撒谎）、错 key 得 verified:false（伪造与损坏对判定不可区分，这本身是设计）。拉格朗日权重只依赖 x 坐标，每子集算一次、全秘密复用——16 KiB 门限 6 的 split 0.23 秒、combine 0.09 秒。

reshare 的代数是项目的技术主菜之一：g = f + h，其中 f 是旧份额蕴含的原多项式，h 是新种子派生的零常数项随机多项式。g 的常数项仍是秘密字节，任何门限的旧份额确定 f 从而确定 g 在新 x 处的值，而新旧份额混合时要么因门限不一致被拒、要么插值出过不了标签的垃圾——这就是 proactive security 的操作化：轮换后销毁旧份额，攻击窗口关闭。白盒测试与 oracle 各自驱动三代链式轮换（2-of-4 升到 5-of-7），并验证伪造 threshold 字段的旧代混入被标签拦截。

## 四 可复现案例

examples/split.json 将 16 字节秘密按 3-of-5 分片并固定种子，报告逐字段锚定；examples/combine.json 取第 1、3、5 份恢复，secret_hex 与标签验证逐位一致。

examples/diagnose.json 在五份中把第五份首字节翻转，diagnose 输出 suspects [5]、good [1,2,3,4]，并仍从排除坏份额的法定人数恢复原秘密——210 个子集的穷举，不靠启发式。

examples/words-split.json 与 words-combine.json 展示纸笔路径：份额以十二个四字母词的序列打印（词 1 是份额序号、词 2 是门限、载荷、两词校验和），取第 1、3 份的词序列交回即还原。五个示例全部由 CLI 实际执行并与钉死的期望输出比对，examples/README.md 逐个说明。

examples 之外有一份负案例：scripts/lowentropy-demo.py 把六位恢复码按 3-of-5 分片后仅持一份份额，对公开标签枚举 10⁶ 候选，2.6 秒还原原码——低熵秘密被单份份额攻破的可执行证明，也是申报书一切门限主张所附条件的来源。

命令行一键复现：`node scripts/shamir.mjs split <hex> 3 5 20261104` 打印一行式份额（index:threshold:digest:encoding:data），任意 k 行交回 combine 即还原；kdf、reshare、diagnose、verify 同为子命令。六个动词的往返全部纳入验证梯。

## 五 验证与实际规模

34 项 MoonBit 测试在四后端全绿、--deny-warn 零告警（另有 2 项 bench 声明计时与 6 项 quickcheck 生成式性质各 300-500 例，均不计入测试数），其中包含 3-of-5 全部 10 个 k-子集的穷举恢复律与 255 份额满环（threshold=255 的退化情形：一个子集、一份不能少）。7 个 CLI 夹具与 9 个锚定示例共 16 项检查、106 条拒绝消息经风格审计（ASCII、小写起始、无句号，拼接续段豁免）。

独立 Python oracle 复算 161 组检查：40 组随机分片逐份额十六进制比对（GF(2⁸) 由生成元 3 的指数/对数表第三条路径构造，SplitMix64 亦为 Python 独立重写）、每组全部 k-子集恢复（大集采样）、15 组注入单比特损坏的 diagnose 对拍（引擎与 oracle 必须点名同一嫌疑人）、10 组 reshare 独立铸币加 5 组三代链、8 组 base64 与 8 组 words 的双编码对拍、6 组口令派生（Python hashlib 的 pbkdf2_hmac）与 6 组 HMAC 认证（Python hmac 模块）的逐字节比对、6 组 HMAC 键长边界（63/64 字节贴 hash-then-pad 分支边缘）、4 组全宽 64 位种子独立重放逐份额对拍（含 >2^53 值，Python 侧从规范重放）、split_many 逐位置与单独分片等价、fingerprint 序无关与翻转敏感、info 好坏校验描述、种子确定性与敏感性、UTF-8 往返、拒绝路径。69 条畸形输入全部单错误对象退出 1。

规模与性能入口：scripts/scale.py 每次验证跑 16 KiB 门限 6 的分片-恢复-验证-重分摊链（1.1 秒，预算 12 秒防退化）、diagnose 在 12 份门限 6 的穷举顶格点名坏份额；两个 moon bench 计时块钉住 1 KiB 门限 5 的 split（212 µs）与 combine（1.75 ms）；公共 API 面冻结于 tests/api.golden，每次验证 moon info 后 diff——导出面任何变动当场红。scripts/stats.py 统计：自有生产物理行 2,634 行（有效 2,229 行，11 个文件），此数字含 256 词表与 RFC 常量表，不含测试、脚本、示例与文档。

## 七 当前边界与来源

纯内存决策库：不落盘、不网络传输、不管理份额的分布式存放，份额如何打印、保管、传递属于调用者。份额 x 坐标 1..255 故 n≤255；秘密 ≤16 KiB；种子以 JSON 数值传输故 ≤2^53−1，口令派生 1..1000000 次迭代。SplitMix64 非密码学原语，可复现性以种子为代价——种子与秘密同级敏感；门限保证为条件式（高熵秘密+均匀满宽种子），低熵秘密被公开标签在单份份额内枚举攻破（含可执行演示），须先拉伸；CRC-32 与 SHA-256 标签防损坏不防伪造，HMAC 标签防伪造但对密钥持有者无效；无侧信道加固主张，words 份额的词数即长度。门限语义不支持增量恢复、可验证秘密分享（VSS）与门限下的乘法（MPC 原语）。

方案本身非首创（Shamir 1979、Blakley 1979 独立提出），域取 AES 多项式，词表编码承 SLIP-39 之意而词表自定（系统词典四字母词按 sha256 排序冻结），HMAC 与 PBKDF2 遵 RFC 2104/8018。未复制其任何源码或测试；不主张算法首创，贡献在于 MoonBit 生态空位的可验证实现、diagnose/verify/reshare 三个外围操作，以及从字段算术到 CI 的完整证据链。MoonBit 生态另有 fulltext 检索与向量索引项目，与本项目无重叠；生态空白主张以 2026-11-04 与 2026-11-11 两次索引快照为限。共同基础代码与 AI 编程辅助见 THIRD_PARTY.md。

本项目提供可运行工具和明确边界。有效工作量、创新性与报名资格仍由组委会审核，公开发布本身不是审核通过的证明。
